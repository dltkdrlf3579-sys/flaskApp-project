사내 AI 조회 도우미 — 이관·설정 매뉴얼
작성: 2026-09-08 / 메모장 UTF-8

먼저 한 줄 결론
포털 코드와 '기존 카카오봇의 검증된 자료 묶음'을 회사 PC에 옮기고,
포털 config.ini에 사내 API 주소·모델·인증값과 자료 폴더를 넣으면 됩니다.
이 연결은 카카오톡 서버를 실행하지 않습니다. 포털이 자료를 검색하고 사내 AI를 직접 호출합니다.

중요한 구분
- 지금 개발한 곳은 개인 개발 노트북입니다. 실제 사내 API·SSO·운영 서버에는 접속하지 않았습니다.
- 카카오봇과 자료·원본·페이지 이미지를 재사용하지만 검색 엔진 전체를 동일하게 복제한 것은 아닙니다.
  카카오의 GPT/임베딩 API를 그대로 사내로 옮기면 외부 연결이 막힐 수 있어,
  이번 연결은 사내 AI의 질문 해석 + 기존 텍스트 색인의 키워드 검색 + 사내 AI 답변 방식입니다.
  새 사내 임베딩 API는 필요 없고 외부 GPT로 자동 우회하지 않습니다.
  검색 정확도와 답변 품질이 기존 카카오봇/GPT와 같다는 보장은 없습니다.
- 문서 검색이지 출입정보·개인 교육이력 등 실제 DB 조회 도구 연결은 아닙니다.
- 질문은 텍스트만 입력합니다. 채팅창에서 사용자 파일/사진 업로드는 이번 범위가 아닙니다.
- public_downloads뿐 아니라 knowledge에 등록된 현행 원본도 제공합니다.
  그렇다고 PC의 모든 파일을 제공하는 것은 아닙니다. 코드, 키, 로그는 대상이 아닙니다.

============================================================
1. 노트북에서 무엇을 준비할까?
============================================================

A. 포털 코드
현재 사용 중인 포털을 기준으로 다음 변경을 함께 옮깁니다.

  ai_assistant.py
  ai_internal_client.py
  portal_ai 폴더 전체
  templates/ai-assistant.html
  static/js/ai-assistant-render.js
  scripts/package_ai_knowledge.py
  requirements-ai.txt
  이 매뉴얼

config.ini는 운영용을 개발용으로 통째로 덮어쓰지 마세요.
아래 3번의 AI 관련 4개 섹션만 운영용에 반영합니다.
DB, SSO, 다른 메뉴, 자동 업로드 토큰은 건드릴 필요 없습니다.
이 작업에 계약평가 시범 코드나 다른 기능의 미완성 파일을 섞을 필요 없습니다.
기존 ai_chat_sessions/messages/results를 그대로 사용하므로 별도 신규 DB 마이그레이션은 없습니다.
테이블이 없는 첫 사용 환경에서는 기존 AI 기능이 테이블을 생성하므로 팀 PostgreSQL의 생성 권한이 필요합니다.

B. 카카오 자료 묶음 만들기
아래는 CMD 기준입니다. 포털 가상환경에 Python이 설치되어 있다는 전제입니다.
원본 카카오 프로젝트를 수정하거나 AI 재처리하지 않습니다. 등록된 원본·색인·관련 이미지 파일만 읽습니다.

  cd /d C:\Users\sanggil\flask-portal
  venv\Scripts\python.exe scripts\package_ai_knowledge.py --source-root "C:\Users\sanggil\kakao_chatbot" --output "C:\Users\sanggil\Desktop\portal_ai_knowledge.zip"

같은 이름의 zip이 이미 있으면 중단합니다. 새 파일명(예: portal_ai_knowledge_20260908.zip)을 사용하세요.
자료가 바뀌는 도중 실행하지 말고 카카오 측 자료 갱신이 끝난 뒤 실행하세요.
출력 파일은 사내 반입 절차에 따라 옮깁니다.

이 zip에 포함되는 것
- cache/knowledge_index.jsonl (기존 승인된 텍스트 색인)
- knowledge/영역/source_registry.json
- 등록된 active 원본 파일
- 활성 원본에 연결된 public_downloads 파일과 목록
- 원본이 knowledge가 아니라 public_downloads에 보관된 자료도 등록 연결과 SHA-256 일치로 확인해 포함
- 검색 페이지에 연결된 페이지 이미지 및 해당 메타데이터
- 이관 무결성 검사용 portal_bundle_manifest.json

포함하지 않는 것
- .env, API 키, 소스 코드, 카카오 서버 설정, 터널 토큰, .git, 가상환경
- OpenAI 임베딩 캐시, 로그, 전체 문서 가공 중간 산출물

왜 통째로 압축 대신 이 도구를 쓰나?
단순 압축 자체도 가능하지만 불필요한 용량·인증정보가 섞이고,
다른 폴더를 가리키는 링크 파일이 실제 원본 없이 옮겨질 수 있습니다.
이 도구는 등록된 원본의 해시를 검사하고 연결 파일도 실제 내용으로 넣습니다.
원본 해시 불일치나 필수 파일 누락이면 중단합니다. 검사를 끄고 밀어 넣지 마세요.
카카오 쪽 정식 자료 검증/색인 절차로 원본·색인을 맞춘 후 다시 묶으세요.

2. 사내 개발 PC에 먼저 풀기
============================================================

예시 폴더 구조 (실제 경로는 자유롭게 바꿔도 됩니다)

  D:\flask-portal\                포털 코드와 config.ini
  D:\ai_knowledge\knowledge\     zip 안의 knowledge
  D:\ai_knowledge\cache\         zip 안의 cache
  D:\ai_knowledge\public_downloads\
  D:\ai_knowledge\artifacts\
  D:\ai_knowledge\portal_bundle_manifest.json

주의: D:\ai_knowledge\portal_ai_knowledge\knowledge처럼 한 겹 더 들어갔다면
root_folder도 그 안쪽 실제 최상위 폴더로 맞춰야 합니다.
포털 하위에 카카오 프로젝트 전체를 넣을 필요가 없습니다. C:와 D:가 달라도 됩니다.

회사 PC의 포털 가상환경에 추가 패키지를 설치합니다.

  cd /d D:\flask-portal
  venv\Scripts\python.exe -m pip install -r requirements-ai.txt

위 venv 이름은 실제 운영 환경에 맞춥니다. 이미 활성화했다면 python -m pip ...도 됩니다.
사내 PC가 인터넷 차단이면 회사에서 허용한 패키지 저장소를 쓰거나,
해당 PC의 Python 버전·Windows 아키텍처에 맞는 wheel과 의존 패키지를 준비해서 설치하세요.
다른 PC의 venv 폴더를 통째로 복사해서 해결하지 마세요.
PyMuPDF는 PDF 페이지 미리보기용입니다. 사용되는 버전의 Python 지원 범위도 확인하세요.

============================================================
3. 운영 config.ini에 무엇을 넣을까?
============================================================

같은 섹션이 이미 있으면 중복으로 추가하지 말고 기존 섹션의 키를 수정합니다.
키값 오른쪽에 실제 값을 넣되 양끝에 따옴표를 붙이지 않습니다.
%, 한글 경로도 읽도록 되어 있습니다. 파일은 UTF-8로 저장합니다.

[AI_ASSISTANT]
enabled = true
mode = internal
real_module_path =
real_module = ai_internal_client
real_function = ask_internal_ai
real_stream_function = ask_internal_ai_stream
mock_stream_delay_ms = 25

설명
- 개발 노트북은 의도적으로 mode = mock을 유지했습니다.
- 사내에서 아래 주소/인증값을 채운 뒤 internal로 바꿉니다.
- real_module_path는 빈 값 그대로입니다. 포털 안에 연결 파일이 있기 때문입니다.
- 이전 AI_DOMAIN_* 섹션은 mock용 분류 참고 설정이며 이번 문서 검색 라우팅에는 쓰지 않습니다.

[AI_INTERNAL_API]
base_url = 사내 작업중지권에서 사용한 API 기본주소
chat_path = chat/completions
model_name =
x_dep_ticket = 발급받은 티켓
send_system_name = 발급받은 시스템명
user_id = API 사용자 ID
user_type = API 사용자 유형
api_key = api_key
prompt_msg_id = auto
completion_msg_id = auto
streaming = true
temperature = 0
max_tokens = 0
connect_timeout_seconds = 10
timeout_seconds = 180
total_timeout_seconds = 240
proxy_url =
verify_ssl = true
ca_bundle =

설명
- 한글 설명으로 쓴 주소/티켓/모델 부분은 반드시 실제 사내 값으로 교체합니다.
- model_name은 아래 세 모델 모드를 끈 경우에만 사용합니다. 세 모델 모드이면 빈 값으로 둡니다.
- 예: base_url이 https://사내호스트/v1이면 실제 요청은 https://사내호스트/v1/chat/completions입니다.
- 완성된 /chat/completions 주소를 base_url에 넣는 경우 chat_path를 빈 값으로 둡니다.
- 헤더는 작업중지권과 같은 x-dep-ticket, Send-System-Name, User-Id, User-Type,
  Prompt-Msg-Id, Completion-Msg-Id를 보냅니다. 요청 ID는 매번 자동 생성합니다.
- api_key는 Authorization: Bearer 뒤의 값입니다. 작업중지권과 같이 티켓 인증이면
  더미값 api_key를 유지하고, 별도 Bearer를 요구하는 API라면 발급값을 넣으세요.
- URL은 API 엔드포인트이지 웹 채팅 화면 주소가 아닙니다.
- API가 SSE 스트리밍을 지원하지 않으면 streaming = false로 설정합니다.
  그러면 진행 상태는 표시하지만 완성된 답변 텍스트가 한 번에 도착합니다.
- 실패했다고 다른 API나 외부 GPT를 자동으로 다시 호출하지 않습니다.
- timeout_seconds는 읽기 대기, total_timeout_seconds는 응답 조각 수신 시 경과시간 검사입니다.
  무응답 상태는 읽기 대기시간의 영향을 받습니다. 전체 질문은 통상 2회 호출이라 이 값의 2배 이상 걸릴 수 있습니다.
- 프록시는 필요할 때만 proxy_url에 넣습니다. API 주소를 프록시 주소로 무조건 복사하지 마세요.
  작업중지권의 OpenAI 프록시 설정이 실제 필요한 환경이라면 회사 담당자에게 확인해 맞춥니다.
- 사내 인증서라면 ca_bundle에 회사 CA PEM 파일 경로를 지정합니다.
  verify_ssl = false를 일반적인 해결책으로 권장하지 않습니다.

[AI_MODEL_ROUTING]
enabled = true
luna_model = 사내 간단 작업용 모델명
terra_model = 사내 일반 답변용 모델명
sol_model = 사내 복잡한 판단용 모델명

설명
- luna/terra/sol은 역할 이름입니다. 오른쪽에는 해당 사내 API에서 허용한 실제 모델명을 넣습니다.
  외부 GPT 모델명을 임의로 넣으면 사내 API가 지원하지 않아 오류가 날 수 있습니다.
- 세 모델은 위 AI_INTERNAL_API의 주소·티켓·헤더·시간 제한을 함께 사용합니다.
  모델마다 다른 주소나 별도 티켓이 필요한 API라면 이 설정만으로는 안 되므로 추가 연결이 필요합니다.
- 루나가 먼저 질문과 이전 대화를 해석하고 답변 담당 역할을 JSON으로 선택합니다.
  루나: 간단한 용어 설명, 파일/사진 요청.
  테라: 일반 규정의 기준·요건·절차 설명.
  솔: 적용 대상 분류, 예외·조건이 얽힌 판단.
- 세 모델에 모두 물어보거나 사용 비율을 맞추는 것이 아닙니다.
  자료 검색 질문은 통상 '루나 해석 1회 + 선택된 답변 모델 1회'입니다.
  루나가 답변 담당이면 루나를 2회 호출합니다. 인사/확인 질문은 루나 1회입니다.
  자료가 없으면 해석 1회 뒤 포털의 안내로 끝납니다.
- 세 모델 모드에서 한 모델명이라도 빠지면 API 호출 전에 중단합니다.
  선택 결과가 luna/terra/sol 밖이거나 API가 실패하면 임의 모델로 재시도하지 않습니다.
- 답변 아래에 실제 답변 모델명과 역할이 표시되고 대화 DB에도 저장됩니다.
  새로고침 후에도 해당 답변 당시의 모델이 보입니다. 기존 과거 답변은 모델 기록이 없을 수 있습니다.
- 선택 기준은 프롬프트이며 질문의 특정 단어를 if문으로 검사해 강제 선택하지 않습니다.
  사내 모델의 실제 분류 품질은 간단/일반/복잡한 대표 질문으로 확인해야 합니다.
- 원래처럼 하나만 쓰려면 enabled = false로 바꾸고 AI_INTERNAL_API.model_name에 모델명을 넣습니다.
  그 경우 동일한 모델이 해석과 답변을 맡습니다. 설정 섹션이 없는 이전 구성도 단일 모드입니다.

[AI_KNOWLEDGE]
enabled = true
root_folder = D:/ai_knowledge
index_file = cache/knowledge_index.jsonl
domains = safety_training,safety_law
reload_seconds = 180
max_results = 8
context_chars = 32000
max_downloads = 6
max_images = 4
preview_cache_folder = .cache/ai_previews

설명
- root_folder만 실제 압축 해제 위치로 바꾸면 됩니다. 기본 주소와 별개입니다.
- domains는 기존 자료 영역명입니다. 폴더에 없는 영역은 넣지 마세요.
- enabled = false이면 자료 없이 일반 대화만 합니다. 파일 제공도 차단됩니다.
  이 경우 세 모델 모드라도 루나로 1회 일반 대화만 하며 복잡도별 답변 선택은 하지 않습니다.
- max_results/context_chars를 늘리면 근거를 더 보내지만 응답 속도·모델 입력 한도에 영향을 줍니다.
- 새 자료를 폴더에 복사만 해서는 검색되지 않습니다. 기존 카카오 자료 등록/승인/색인을 완료하고
  새 묶음을 이관해야 합니다. AI 학습자료 업로드 게시판과 이 색인은 아직 자동 동기화되지 않습니다.
- reload_seconds는 이미 만들어진 색인/목록 파일의 변경 확인 주기이지 새 문서 학습 주기가 아닙니다.
- 미리보기 캐시 폴더에는 운영 계정의 쓰기 권한, 원본 자료 폴더에는 읽기 권한이 필요합니다.

============================================================
4. API 연결 전에 자료 점검하기
============================================================

  cd /d D:\flask-portal
  venv\Scripts\python.exe scripts\package_ai_knowledge.py --check

확인하는 것: 등록 목록, 원본 해시, 색인, 연결 파일, 압축 이관 해시, 패키지 설치 여부, 필수 API 설정과 세 모델명.
하지 않는 것: API 호출, 문서 재학습, DB 쓰기, 운영 SSO 인증 확인.
실제 API가 정상인지까지 이 명령만으로 확인했다고 생각하면 안 됩니다.

============================================================
5. 서버 재시작과 실제 사내 확인
============================================================

먼저 사내 개발 PC localhost에서 확인하고, 통과한 뒤 가상 서버에 같은 변경을 배포합니다.
개발 노트북의 주소/설정/가짜 데이터를 운영 환경에 맞다고 가정하면 안 됩니다.

켜져 있는 포털 터미널에서 Ctrl+C → 종료된 것을 확인 → 원래 실행 방식으로 재시작.

개발 PC에서 기존 Flask 방식이라면:
  python -m flask run
  접속: http://127.0.0.1:5000/ai-assistant

기존 운영 Waitress 방식이라면 (원래 가상환경 활성화 후):
  waitress-serve --listen=127.0.0.1:44369 --threads=32 --backlog=2048 --channel-timeout=60 --connection-limit=1000 wsgi:app
  접속: http://127.0.0.1:44369/ai-assistant

다른 PC에서는 127.0.0.1이 서버를 뜻하지 않습니다. 원래 사용하던 사내 포털 주소로 접속합니다.
SSO 설정과 AI_ASSISTANT 읽기 권한은 기존 운영 설정을 유지합니다. 이 기능에 쓰기 권한은 필요 없습니다.
화면이 이전 그대로면 브라우저 강력 새로고침(Ctrl+F5), 실행 폴더와 실제 포트부터 확인합니다.

직접 확인할 질문 순서
  1) 실제 자료 제목/주제를 넣고 '이 규정을 요약해줘'
  2) 같은 대화에서 '그 원본 파일을 줘'
  3) '그 내용이 있는 페이지를 사진으로 보여줘'
  4) 파일 다운로드와 사진 확대가 열리는지 확인
  5) 새로고침 후 대화와 파일/사진 링크가 그대로 복원되는지 확인
  6) 다른 사용자 ID로 접속해 이전 사람의 대화가 안 보이는지 확인
  7) AI_ASSISTANT 권한 없는 계정으로 채팅·다운로드 직접 주소가 차단되는지 확인
  8) 준비한 대표 업무 질문에서 실제 원본과 답변의 조건/예외/수치가 일치하는지 확인
  9) 간단 요청/일반 규정/조건·예외 판단 질문을 각각 보내고 답변 하단의 역할과 실제 모델명 확인
     항상 동일한 모델이 선택된다면 사내 모델의 JSON 선택 결과와 프롬프트를 점검합니다.

사내 프록시가 응답을 모아서 전달하면 streaming=true여도 글이 한 번에 보일 수 있습니다.
외부망 개발 테스트만으로 운영 프록시·SSO·방화벽 문제는 검증할 수 없습니다.

============================================================
6. 질문이 실제로 처리되는 순서
============================================================

웹 질문
→ 포털의 메뉴 권한과 로그인 확인
→ 팀 PostgreSQL에서 내 대화방의 최근 12개 메시지(합계 약 12,000자 이내)와 출처를 읽음
→ 루나 API 1차 호출: 질문/후속 맥락/등록 자료 목록을 보고 검색어·파일/사진 요청과 답변 담당을 JSON으로 선택
→ 포털이 기존 텍스트 색인에서 검색 (DB 메뉴/SQL을 AI 마음대로 실행하지 않음)
→ 선택된 루나/테라/솔 중 한 모델 API 2차 호출: 검색된 근거로 설명 작성, [S1] 등의 출처 표기
→ 답변 조각을 브라우저에 바로 전달
→ 실제 사용한 출처에 연결된 파일/페이지 카드를 서버가 붙임
→ 메시지와 출처·파일·이미지·사용 모델 정보를 PostgreSQL에 저장한 뒤 완료 표시

대화는 사용자별로 분리합니다. 공유 문서는 AI 읽기 권한이 있는 사용자에게 제공됩니다.
대화 전체가 무한히 모델에 들어가는 것은 아닙니다. 오래된 질문은 문서명을 다시 말하거나 새 대화로 시작하세요.
단순 인사/확인 질문은 1회, 자료를 못 찾으면 1회로 끝날 수 있습니다.
세 모델 모드를 끈 경우에는 이 두 호출에 AI_INTERNAL_API.model_name의 동일한 모델을 사용합니다.

사진은 어떻게 나오나?
- 기존 문서 처리 때 준비된 해당 페이지 이미지가 있으면 재사용합니다.
- 없더라도 원본이 PDF이면 해당 페이지를 서버에서 PNG로 만들어 표시합니다.
- 원본이 PNG/JPG 등 이미지이면 원본 이미지를 제공합니다.
- Word/Excel/PPT는 기존 페이지 이미지가 있어야 캡처를 보여줍니다. 없는 것을 자동 Office 렌더링하지 않습니다.
- 이번 구현은 관련 페이지 전체 표시입니다. 원하는 그림 영역만 정밀하게 잘라주는 기능은 아닙니다.
- 그림의 의미를 새로 비전 AI가 분석하는 기능은 아니며, 기존 승인된 텍스트 색인을 이용해 페이지를 찾습니다.

============================================================
7. 자주 막히는 지점
============================================================

화면에 mock 표시
  [AI_ASSISTANT] mode가 아직 mock입니다. 실제 설정을 채운 뒤 internal로 바꾸세요.
  mock에서 '의도를 분석 중'이라는 말이 나와도 실제 사내 모델이 실행되는 것은 아닙니다.

설정 누락 / HTTP 401·403
  API 발급값, 헤더, SSO 권한을 구분해서 확인하세요. 사내 API 인증과 포털 사용자 권한은 별개입니다.
  연결부에 넣는 user_id는 API 호출용 ID이며 포털 대화 소유자 SSO ID를 덮어쓰지 않습니다.

HTTP 404 / 400
  base_url와 chat_path 중복 여부, 모델명과 Chat Completions 요청 규약을 확인합니다.

자료 경로가 폴더 밖을 가리킴
  원본이 다른 폴더 링크일 수 있습니다. 1번의 자료 묶음 도구로 실제 파일을 포함해서 옮기세요.

원본과 검색 자료 버전이 다름
  원본만 새로 바꾸지 말고 기존 카카오의 검증된 색인·원본 묶음을 같은 시점으로 맞추세요.

AI 검색 JSON 형식 오류
  모델이 요청 형식을 따르지 못한 경우입니다. 모델/프롬프트 확인이 필요합니다.
  세 모델 모드는 기존 검색 필드에 author_choice(luna/terra/sol)와 routing_basis(짧은 선택 사유)가 추가됩니다.
  자동으로 임의 키워드에 끼워 맞추거나 외부 GPT로 우회하지 않습니다.

파일은 있는데 검색이 안 됨
  파일이 active 등록 자료인지, 색인에 들어 있는지, 도메인 설정이 맞는지 확인합니다.
  현재 검색은 키워드 기반이므로 동의어나 정확한 문서명을 넣어 비교하세요.

그림 안 보임
  원본/페이지 산출물 누락, PyMuPDF 미설치, 서버 계정 폴더 권한, PDF 암호화를 확인합니다.
  연결된 문서 원본은 '확인한 출처' 카드로도 다운로드할 수 있습니다.

답변이 도중에 끊김
  API/프록시 시간제한, 출력 길이 제한 등을 확인합니다. 중간 답변을 완료된 것으로 간주하지 않습니다.
  비용과 중복 대화를 막기 위해 자동 재요청하지 않습니다. 이력을 확인한 뒤 사용자가 다시 질문합니다.

급하게 원래 데모로 복구
  운영 config.ini의 [AI_ASSISTANT] mode = mock으로 변경하고 포털을 재시작합니다.
  대화 DB와 자료 파일을 삭제할 필요는 없습니다. 기능 자체를 중단하려면 enabled = false로 합니다.
