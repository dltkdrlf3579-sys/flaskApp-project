# AX EHS Navigator 대시보드

## 화면과 범위

- 상단 `AX EHS Navigator → 대시보드`, URL `/ax-ehs-navigator`.
- 현재 상태만 조회하며 과거 기간 필터, 공지, 새로고침, 별도 소메뉴 탭은 없습니다.
- 최초 샘플은 계약평가만 포함합니다. 포탈의 기존 계약평가 등록/AI 채점 기능과는 별개의 QADB 집계 화면입니다.
- 업무마다 INI에 쿼리와 집계 단위를 지정합니다. 업체 공통 업무와 사업장별 업무는 상단 카드·업무 그래프·협력사 조회에서 함께 집계하며, 사업장 표에는 사업장별 업무만 들어갑니다.
- 협력사 상세는 **업체 공통 업무 / 사업장별 업무**로 구분합니다. 사업장별 업무는 사업장과 업무명을 함께 표시합니다.
- 상단 카드·업무 그래프·사업장 표·협력사 현황은 모두 `[STATUS_COLUMNS]` 순서와 색상으로 상태를 각각 표시합니다. **미완료에는 진행중·기한초과를 합산하지 않습니다.** 상태 판단은 SQL 결과를 그대로 사용합니다.
- 일반 데스크톱(1366×768, 1920×1080, 배율 100%)의 한 화면 구성을 목표로 합니다. 좁은 화면/큰 확대율에서는 가독성을 위해 세로 배치로 전환합니다.
- 업무·사업장·비정상 목록은 화면에 일부만 표시하고 전체 보기는 대화상자로 제공합니다. 협력사 검색과 업무별 상세도 같은 조회 결과를 사용합니다.

## 실제 쿼리 교체

설정은 프로젝트 루트 `navigator_config.ini`입니다. UTF-8로 저장하세요. 다음 페이지 조회부터 다시 읽습니다.

1. `[WORK:contract_evaluation] query`를 실제 계약평가 QADB SELECT로 교체합니다. `scope = company`이므로 사업장 컬럼이 필요하지 않습니다.
2. `[QUERIES] exceptions`를 비정상 업무 조회로 교체합니다. 미연계라면 값을 비워 두세요.
3. `[NAVIGATOR] source = qadb`로 변경합니다. 기존 `database_config.execute_SQL` / IQADB 연결을 사용하므로 접속정보를 중복 저장하지 않습니다.
4. 사내 개발 PC에서 실제 QADB 컬럼·권한·집계 결과를 확인한 후 가상 서버에 적용합니다.

기본 `sample_postgres`는 INI의 상수 SELECT를 포탈 PostgreSQL에 **읽기 전용 트랜잭션**으로 실행합니다. 샘플 행을 DB에 저장하지 않습니다. 화면에는 예시 데이터가 표시됩니다. QADB 실패 시 로컬/샘플로 대체하지 않으며 오류를 표시합니다. 로컬 결과는 사내 연동 성공을 보장하지 않습니다.

## 업무 추가와 집계 단위

```ini
[WORK:contract_evaluation]
name = 계약평가
scope = company
enabled = true
query =
    SELECT ...

[WORK:subcontract_report]
name = 도급신고
scope = site
enabled = false
query =
    SELECT ...
```

`WORK:` 뒤는 업무 고유 ID이고 `name`은 표시명입니다. `name`을 생략하면 고유 ID를 표시합니다. 고유 ID는 업무끼리 겹치지 않아야 하며 한국어도 가능합니다. `scope`는 필수이며 아래 두 값만 사용합니다.

| scope | 쿼리의 집계 단위 | 반영 위치 |
| --- | --- | --- |
| company | 협력사 × 담당자 × 부서. 사업장 불필요 | 전체 카드, 업무 그래프, 협력사 조회, 업체 공통 상세 |
| site | 협력사 × 사업장 × 담당자 × 부서 | 전체 카드, 업무 그래프, 사업장 표, 협력사 조회, 사업장별 상세 |

업무를 추가할 때 `[WORK:고유ID]`를 복사하고 `name`, `scope`, `query`를 설정하면 됩니다. 업무별 쿼리를 프로그램이 각각 조회하고 합산하므로 **여러 업무를 하나의 UNION ALL로 합칠 필요가 없습니다.** 샘플에 있는 UNION ALL은 한 업무 안에서 개발용 상수 행을 만드는 용도입니다.

`enabled = false`인 업무는 쿼리를 실행하지 않고 모든 집계에서 제외합니다. 초기 설정의 도급신고·원하청 공동위험성평가 예시는 꺼져 있습니다. 실제 쿼리를 넣은 뒤 true로 바꾸세요. enabled를 생략하면 true입니다.

사업장 표는 **사업장 단위 업무 기준**이므로 전체 대상 업무와 합계가 달라도 정상입니다. 계약평가를 사업장마다 복제하지 않습니다. 사업장 업무가 모두 꺼져 있으면 미연계 안내를 표시하고, 켜져 있으나 조회 결과가 없으면 조회 범위에 데이터가 없음을 표시합니다.

## 업무 쿼리 결과 규칙

한 업무 안에서 위 표의 단위를 중복 없이 반환해야 합니다. 같은 업무 건을 여러 담당자 행에 복제하면 안 됩니다. 담당자별로 나누기 어렵다면 전체 조회 권한용 집계를 반환하고 owner 식별자는 빈 문자열로 둡니다. 이 경우 본인/부서 권한에는 노출되지 않습니다.

| 컬럼 | 의미 |
| --- | --- |
| partner_id / partner_name | 협력사 고유 ID / 표시명. 같은 회사의 ID는 일관되어야 합니다. |
| tier | 1차·2차 등 구분 |
| site | scope = site일 때 필수. company에서는 생략 가능하며 반환해도 사업장 집계에 사용하지 않습니다. |
| owner_login_id / owner_dept_id | 포탈 로그인 ID / 부서 ID와 같은 체계의 문자열. 권한 범위 필터에 사용 |
| 완료 / 미완료 / 기한초과 / 진행중 | 샘플 상태별 건수. 서로 배타적이며 합계가 전체 대상 업무 |
| gate_completed / gate_incomplete | 선택 사항. 둘 다 생략하면 0. 반환하면 완료 상태 합계 / 완료 외 상태 합계의 부분집합 |

`work_name` 컬럼은 새 업무별 쿼리에서 필요하지 않습니다. 업무명과 단위는 해당 WORK 섹션의 설정을 사용합니다. 업체 공통 행을 사업장만 바꾸어 여러 번 반환하면 중복 조회 오류로 처리합니다.

SQL 상태 별칭을 변경하면 `[STATUS_COLUMNS]`의 키도 동일하게 변경합니다. 예: **사용 중인 모든 업무 쿼리**에 `... AS "검토대기"`를 추가하고 `검토대기 = #9c73d7`을 추가하면 상단 카드·범례·그래프·사업장 및 협력사 현황·두 종류의 상세 표에 반영됩니다. 해당 업무에서 사용하지 않는 상태도 `0 AS "검토대기"`를 반환해야 합니다. 꺼 둔 업무도 활성화하기 전에 같은 컬럼을 준비하세요. `completed_columns`는 Gate 부분집합 검증용이며 상태를 화면에서 합치는 설정이 아닙니다. 상태가 많아지면 카드는 줄바꿈하고 제한된 영역 안에서 스크롤되며, 넓어진 표는 영역 안에서 가로 스크롤됩니다.

모든 상태 컬럼은 숫자형 0 이상의 정수여야 합니다. 해당 건이 없으면 NULL 대신 0을 반환하세요. 컬럼 이름은 대소문자를 구분하지 않습니다. 쿼리가 0행이어도 필수 컬럼은 있어야 합니다. 식별자 누락, 중복 집계 행, 잘못된 건수는 0으로 숨기지 않고 조회 오류로 처리합니다. SQL의 `%` 문자는 ConfigParser 보간 없이 보존됩니다.

관리 대상 협력사 수는 켜진 업무 쿼리 전체의 고유 partner_id 수입니다. 여러 업무와 사업장에 나타나도 한 업체로 셉니다. 업무가 없는 협력사도 포함하려면 필수 식별자와 상태 0을 가진 행을 반환해야 합니다. 등록 자체가 누락된 업무를 자동 추정하지는 않습니다.

기존 서버 설정에 `[QUERIES] workload`만 있으면 종전 사업장 집계 형식도 계속 지원합니다. 이 경우 `site`, `work_name`, Gate 두 컬럼까지 필수이고 모든 행은 사업장 업무로 취급합니다. 새 WORK 형식으로 옮길 때 기존 workload 항목을 제거하거나 비우세요. 두 형식을 함께 쓰면 오류로 처리하여 중복 집계를 막습니다. 기존 쿼리의 업무 단위를 자동 추측하지 않습니다.

## exceptions 결과 규칙

`exception_id, partner_id, partner_name, work_name, issue, status, category, owner_name, owner_login_id, owner_dept_id`를 반환합니다. `site`는 선택 사항이며 업체 공통 업무에서는 생략하거나 빈 문자열을 반환하면 화면에 '업체 공통'으로 표시합니다. 1행은 중복 없는 조치 항목 1건이며 exception_id는 고유해야 합니다. 조회 순서가 화면 우선순위이므로 실제 쿼리에 적절한 ORDER BY를 지정하세요. category는 비정상 유형, issue는 확인 내용입니다. 날짜 계산이나 자동 이상 판정은 쿼리에서 수행합니다. exceptions는 별도 쿼리이므로 켜진 업무 범위에 맞게 직접 구성합니다.

## 비정상 현황 엑셀 다운로드

비정상 진행 현황 제목 오른쪽의 **엑셀 다운로드**로 RawData 시트를 가진 `.xlsx` 파일을 받습니다. 별도 INI 쿼리나 접속정보는 필요하지 않습니다.

- 클릭 시 기존 `[QUERIES] exceptions`를 다시 조회하며, 본인/부서/전체 읽기 권한을 서버에서 적용합니다. 화면의 일부 행 제한 없이 해당 권한 범위의 전체 항목을 내려받습니다. 조회 시점이 달라지면 화면을 처음 열었을 때와 결과가 달라질 수 있습니다.
- SQL 결과의 컬럼 순서와 별칭을 사용합니다. 쿼리에 추가한 상세 컬럼도 자동으로 포함합니다. 권한 필터용 `owner_login_id`, `owner_dept_id` 두 컬럼은 제외합니다. 업체 공통 업무의 생략된 site를 임의로 추가하지 않습니다.
- 항목·협력사 ID와 코드 문자열은 텍스트로 보존합니다. 숫자와 날짜는 Excel 자료형으로 기록하고, 시간대가 있는 날짜/시간은 한국 시간으로 변환합니다. `=`로 시작하는 원본 문자열도 수식으로 실행되지 않게 텍스트로 기록합니다.
- 첫 행을 고정하고 자동 필터를 넣습니다. 미연계 또는 화면의 조회 결과가 0건이면 버튼을 비활성화합니다. 조회 실패는 오류로 표시하며 빈 파일로 대체하지 않습니다.
- API는 `/api/ax-ehs-navigator/exceptions/export`입니다. 페이지와 동일한 Navigator 읽기 권한이 필요하고 브라우저 캐시를 저장하지 않습니다.

## 권한

- 권한 코드: `AX_EHS_NAVIGATOR`. 기존 사용자/부서 권한 설정과 신청 목록에 자동 연결됩니다.
- 페이지와 API 모두 조회 권한이 필요합니다. 신규 사용자에게 권한을 자동 부여하지 않습니다.
- config.ini에 Navigator 전용 승인 기본값을 추가하지 않습니다. 기존 공통 승인 로직을 따르며, 별도 설정이 없으면 조회 신청은 읽기 1/쓰기 0, 조회·쓰기 신청은 읽기 1/쓰기 1입니다. Navigator 자체에는 쓰기 기능이 없습니다.
- 읽기 1: 본인 / 2: 본인 또는 동일 부서 / 3: 전체. 모든 지표·협력사 검색·비정상 목록은 **서버에서 권한 범위를 거른 뒤** 집계됩니다.
- 전체 QADB 결과는 서버 메모리에서 범위를 거릅니다. 브라우저에는 해당 범위의 집계/목록만 전달하고 권한용 로그인/부서 ID는 내보내지 않습니다. 대량 데이터에서는 소유자 단위 사전 집계 쿼리를 사용하세요.
- Navigator는 별도 조회 권한을 가진 통합 화면입니다. 원본 게시판 접근 권한을 추가로 요구하지 않으므로 관리자는 통합 조회 범위를 고려해 부여해야 합니다.
- 아직 만들지 않은 하위 페이지의 빈 메뉴는 추가하지 않았습니다.

## 검증

`python -m unittest discover -s tests -p test_navigator.py`로 업체/사업장 혼합 집계, 상세 분리, 상태 확장, 업무 활성화, 종전 쿼리 호환, 범위별 집계, 권한 차단, 오류 처리, 메뉴/신청 연결을 검증합니다. 실제 앱 import/초기화 없이 독립 Blueprint에서 검증합니다.

2026-09-28 업무별 집계 단위 검증: 자동 테스트 27개 통과. 실제 PostgreSQL 상수 SELECT와 기존 base.html을 사용하는 독립 화면에서 계약평가만 조회 / 업체·사업장 업무 혼합 조회 / 검토대기 상태 추가를 확인했습니다. 1366×768, 1920×1080에서 페이지 스크롤 없이 표시되고 협력사 상세가 두 종류의 업무로 구분됩니다.

2026-09-29 비정상 현황 엑셀 다운로드 검증: 자동 테스트 33개 통과. 권한별 행 범위, 전체 행과 추가 컬럼, 원본 자료형, 수식 형태 문자열, 미연계와 조회 오류를 검증했습니다. 독립 화면에서 실제 버튼으로 내려받은 XLSX의 행·컬럼·필터·첫 행 고정을 확인했고, 0건일 때 버튼 비활성화와 다운로드 오류 후 재시도를 확인했습니다. 1366×768 화면의 페이지 스크롤은 발생하지 않습니다.

현재 계약평가 샘플: 협력사 4개 / 전체 4건 / 완료·미완료·기한초과·진행중 각 1건. 사업장 예시 업무까지 켠 검증에서는 전체 11건, 사업장 업무만 7건입니다. 실제 설정의 사업장 예시 업무는 꺼져 있습니다. 기존 앱의 SSO/사내 QADB 연결은 로컬 검증에 포함되지 않습니다.
