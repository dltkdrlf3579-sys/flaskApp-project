# 사내 AI 도우미 연결 체크리스트

작성일: 2026-09-08. 사외 개발 노트북에서 구현하며 실제 사내 API·SSO·서버 연결 검증은 사내 PC에서 한다.

## 목표와 경계

- 기존 포털 대화방·소유자별 이력·권한을 유지하고 작업중지권과 같은 사내 LLM 호출 규약을 설정으로 제공한다.
- 질문은 텍스트만 받는다. 답변은 글, 등록된 원본 파일 링크, 관련 문서 페이지 이미지로 구성한다.
- 카카오 챗봇 원본과 운영 프로세스는 수정하거나 실행하지 않는다. 기존 승인된 검색 자료를 읽기 전용으로 재사용한다.
- 사내에서 문서 파일 제공은 public_downloads에만 제한하지 않되, 설정한 자료 폴더의 등록 자료만 허용한다. 소스 코드·인증 설정·로그·임시 파일이나 임의 디스크 경로는 제공하지 않는다.
- 외부 GPT 자동 호출, 신규 문서 전처리, 전체 색인 재생성, 운영 서버 접속, Git 커밋·푸시는 하지 않는다.
- 같은 자료를 이용하더라도 사내 모델의 품질·속도가 GPT와 같다고 보장하지 않는다. 검색용 모델/색인 호환 제약은 문서에 명시한다.

## 5. 세 모델 역할 분담 추가 (2026-09-08 요청)

사용자 승인 범위: 포털에도 카카오처럼 루나 해석 → 검색 → 루나/테라/솔 중 한 모델이 답변하는 선택 구조를 추가한다. 카카오 원본은 수정하지 않는다. 모델의 의미 판단을 키워드 if문으로 대체하지 않는다.

- [x] 공통 API 연결과 역할별 세 모델명 설정, 미입력·잘못된 설정 차단.
- [x] 루나 해석 결과의 모델 선택 및 짧은 선택 사유를 닫힌 규약으로 검증.
- [x] 간단 요청/일반 규정/조건·예외 종합 판단에 따른 단일 답변 모델 호출.
- [x] 선택 모델을 화면과 저장 대화에 표시, 단일 모델 모드 호환 유지.
- [x] 세 선택 경로, 호출 순서·횟수, 실패 시 자동 우회 금지, 기존 파일·이미지·권한 회귀 검증.
- [x] 이관 매뉴얼·설정 설명·최종 검증 기록 갱신.

사내 모델의 실제 이름·지원 여부·선택 품질은 회사 환경에서 검증한다. 세 모델의 응답을 모두 합치거나 다수결하는 구조는 아니다.

### 세 모델 추가 검증 기록

- `portal_ai/routing.py`에서 루나/테라/솔 역할을 닫힌 목록으로 관리한다. URL·티켓·헤더는 `[AI_INTERNAL_API]` 공통 설정이며 모델명만 `[AI_MODEL_ROUTING]`에서 지정한다.
- 루나의 JSON 선택 결과에 따라 검색 근거를 한 답변 모델에 전달한다. 인사/확인 질문은 루나 1회, 근거 없음은 해석 1회 뒤 서버 안내, 자료 검색을 끈 일반 대화는 루나 1회로 끝낸다.
- 가짜 HTTP API + 격리 PostgreSQL 검사 **110개 통과** (기존 57개 포함). 세 역할 모두 해석→선택 모델의 정확한 2회 호출, JSON/SSE 경로, 기존 단일 모델 모드, 모델명 누락 사전 차단, 잘못된 선택·답변 API 오류 시 임의 모델 우회 금지, 권한·개인별 이력·출처·파일·이미지 유지 확인.
- 실제 모델 판단 정확도를 가짜 응답으로 증명한 것은 아니다. 동일 질문에 가짜 API가 각 선택을 반환하도록 만들어 서버가 선택 결과대로만 호출하는지 검증했다. 사내 API를 통한 의미 분류 품질은 위 미완료 항목에 남긴다.
- Edge headless **11개 검사 묶음 통과**. 테라 답변 모델 표시, 새로고침 복원, 같은 대화에서 루나/솔로 선택 변경 및 각 2회 호출, 파일 다운로드·페이지 이미지·HTML 안전 처리·오류 재호출 방지를 확인했다.
- Python 3.9 문법 파싱 통과. 로컬 현재 설정은 `mode = mock` 유지, 세 사내 모델명은 미입력 상태이다. 사내에 설정을 옮길 때 이관 매뉴얼의 AI 관련 4개 섹션을 참고한다.
- 검증 서버 5014/5015 종료, 임시 PostgreSQL 스키마와 생성 자료 제거 확인. 기존 5000 개발 서버와 두 원본 프로젝트는 변경하지 않았다. 이번 요청으로 Git 커밋/푸시는 하지 않았다.

## 구현 결정과 검증 기록

- 이관 매뉴얼: `docs/ai-assistant-company-transfer.txt` (UTF-8).
- API 어댑터: `ai_internal_client.py` → `portal_ai/pipeline.py` → `portal_ai/client.py`.
- 작업중지권과 같은 Chat Completions 요청/응답 및 티켓·시스템·사용자·요청 ID 헤더를 사용한다. 값은 운영에서 입력하며 기존 작업중지권의 비밀값을 복사하지 않았다.
- 카카오 G+TC9 전체 실행 흐름은 복제하지 않았다. 사내 임베딩 API 정보가 없으므로 기존 `knowledge_index.jsonl`의 승인된 텍스트를 독립 키워드 검색에 재사용한다. 사내 AI가 검색어와 후속 문서 대상을 해석하고, 검색된 페이지 근거를 다시 사내 AI에 전달한다.
- 검색 페이지의 인접 조각도 제한된 분량 안에서 함께 제공하지만 전체 문서의 조건을 완전하게 검토했다는 의미는 아니다. 실제 규정 질문 정확도는 사내에서 원본과 대조해야 한다.
- 포털 UI의 DB 도메인 카드는 실제 연결 범위에 맞게 자료 안내로 변경했다. 출입/개인 교육이력 SQL 실행은 이번 기능에 없다.
- 원본 위치를 `knowledge/.../docs`라고만 가정하면 안 된다. 일부 active 원본은 `public_downloads`에 있다. 등록 연결과 원본 SHA-256이 모두 맞는 파일로 해석하고 원본/다운로드 중복 카드를 제거한다.
- `scripts/package_ai_knowledge.py`: 기존 승인된 원본·색인·연결 페이지를 압축하고 manifest를 생성한다. 링크 원본은 실제 내용으로 포장한다. 갱신 도중 색인이 바뀌면 중단한다. API 호출·재색인·원본 수정은 없다.
- 로컬 실제 카카오 자료 읽기 전용 점검: active 원본 92개, 색인 약 2.5만 조각, 이관 대상 2,961개 파일(약 1.03 GB, 압축 전). 등록 원본 해시 및 연결 파일 존재 확인. 이 수치는 점검 시점이며 카카오 쪽 자료 갱신에 따라 변할 수 있다. 전체 실제 자료 zip 생성/사내 배포는 하지 않았다.
- `requirements-ai.txt`에 PDF 렌더링용 PyMuPDF와 requests 명시. 개발 가상환경에 설치해 렌더링했다. 운영 PC 패키지는 별도 설치해야 한다.
- 검증 스크립트 `.tmp/ai_internal_validation.py`: 가짜 localhost Chat Completions 서버 + 격리 PostgreSQL 스키마에서 **57개 검사 통과**. 정상/JSON 전용 응답, 한글 스트리밍, 헤더, 후속 대화 출처, 파일/페이지 제공, 개인별 이력 분리, 읽기 권한, 거부 계정, 파일 버전, 경로 이탈, 기존 페이지 재사용, 압축/복원, 타임아웃, 잘못된 JSON, 중단된 답변, DB 저장 실패, mock 유지, 변경 중 색인 차단을 검사했다.
- `.tmp/ai_internal_browser.cjs`: Edge headless로 표/강조, 파일 실제 다운로드(한글명), PDF 이미지 로드, 새로고침 복원, 후속 질문, HTML/외부 링크 비활성, 오류 자동 재호출 방지 및 스크립트 오류 없음 확인. 외부 CDN 요청을 차단한 격리 페이지에서 확인했으며 사내 프록시/기존 전체 공통 화면을 검증한 것은 아니다.
- 브라우저 검사에서 최초 이력 로딩과 새 대화가 겹쳐 응답이 화면에서 사라지는 타이밍 문제를 재현·수정하고 재검증했다. 완료 이벤트는 DB 저장 성공 뒤에 한 번만 전송하도록 고쳤다.
- 이미지 기록: `.tmp/ai-internal-desktop.png`, `.tmp/ai-internal-mobile.png`. 가짜 API와 검증용 문서 화면이며 실제 사내 모델의 품질 증거가 아니다.
- Python 3.9 문법 파싱, UTF-8 검사, 다른 실행 폴더에서 config 경로 해석, `git diff --check` 통과. 실제 Python 3.9 실행환경 검증은 아니며 운영 패키지 지원 여부는 별도 확인한다.
- 검증 서버(5014/5015) 종료, 임시 PostgreSQL 스키마와 생성 문서 제거 확인. 검증 코드·로그·스크린샷만 Git 제외 폴더 `.tmp`에 보관한다.
- 기존 개발 서버(5000), 운영 서버, 카카오 프로젝트 코드·인증값·실행 프로세스는 변경하지 않았다. 개발 설정은 `mode = mock`으로 유지한다. 기존의 다른 미완성 기능 변경은 보존했으며 Git 커밋/푸시는 하지 않았다.
